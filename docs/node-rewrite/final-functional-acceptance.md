## 已固定的边界（不是待开发功能）

- 候选路由及其S06兼容问题由用户明确冻结，后续重新设计，本轮不改配置或迁移它。
- 网关不能让签名在不同供应商间自动具备有效性；严格保留、有损选择和不可表达内容拒绝均已实现。这是可验证的协议契约，不以“所有供应商签名认证”无限延长任务。
- 服务端函数工具闭环完成后发送缓冲SSE，与Messages旧实现方式一致；原生Responses保持实时SSE。Chat/Responses的抓取证据用标注文本保留，不伪造供应商原生引用。生产首字延迟/容量优化后置。
- 多轮部分用量的数值按已报告轮次累加，与Python核心计数规则对齐，附加不完整标记。汇总不可替代逐轮账本或供应商账单。
- worker仍显式启用，避免启动API即自动访问用户上游。`docker compose --profile recovery up -d --build`是部署启用方式；本轮未开启用户开发库的自动探测。
- UUID/旧ID映射、设备主动拒绝/共享限流、额外出站防护和显式模型目录是已实现的Node契约，保留差异说明，不登记成待开发模块。
- 故障验证推进的是隔离库的到期时间，不谎称等待了生产完整TTL；实际进程抢占、强杀、恢复执行均真实发生。生产容量/供应商费用不是本轮功能通过条件。

## 验证结果

- 针对工具与签名：2文件38项通过。
- 一次完整工作区测试：前端24文件100项通过；后端首轮1594通过、1失败、2跳过。唯一失败是补验用例恢复请求用了与API夹具不同的加密配置；改为真实API调用后，受影响的进程恢复/探测4项全部通过。未重复全量。两项跳过属于需显式开关的通用任务调度器E2E，不是网关占位。
- 两进程补验最初还遗漏断言第二进程被拒绝时新增的零用量记录，已修正为同时核对拒绝与interrupted记录，不是删除有效业务记录以让断言通过。
- 工作区类型检查、API/Web构建、网关静态门禁通过。全量测试已包含gateway、migration-chain、setup-once，因此不再用非static门禁重复执行同一套。构建仍提示既有大chunk，属于后续性能优化。
- 构建后的独立worker在测试配置中验证了禁用探测状态日志和SIGTERM正常退出，没有开启任何实际探测。
- 新增1个工具组合回归和3个页面业务流程用例，扩展既有进程恢复与策略拒绝断言；没有增加另一套重复测试或真实付费压测。
- 没有改Python参考源码、用户账号/路由/密钥或Codex配置；没有新数据库迁移、提交、推送或发布。
