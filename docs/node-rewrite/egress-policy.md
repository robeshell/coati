# 上游出站策略

平台账号与个人渠道使用独立连接池，策略由服务器端账号归属/管理接口权限决定，客户端不能提交标记提权。模型发现、手动/后台健康检查和实际调用采用同一策略。

- 平台上游：域名解析为198.18.0.0/15或2001:2::/48时允许连接，以兼容本机Fake-IP代理。只豁免域名解析结果，不接受直接填写这些保留IP。其他内网、环回和元数据地址仍被拒绝。Fake-IP兼容基于平台配置者及部署网络可信，不代表这些地址本身是公网。
- 个人渠道：不享有Fake-IP例外，继续校验并固定目标及代理IP；不会复用平台连接池，也不会继承部署者的平台代理。
- 平台账号配置的代理：作为管理员指定的可信出口，通过标准HTTP转发/CONNECT保留目标域名，由代理解析目标。代理负责实际目的地址的网络访问控制；网关仍拒绝明文HTTP/内网字面目标（除非部署者此前明确开启私网访问）。TLS继续校验证书和目标域名，重定向不自动跟随。
- 可选GATEWAY_TRUSTED_PROXY_URL：部署者为没有账号级代理的平台上游提供默认可信代理。不会自动读取操作系统设置或修改代理配置。账号级代理优先。

原有GATEWAY_ALLOW_PRIVATE_UPSTREAMS是部署者主动允许私网访问的全局选项，本次不启用它。上述严格约束描述该选项为false时的默认行为。

本次本机无Key访问DeepSeek /models，平台路径收到401（连接与TLS成功），个人路径仍在Fake-IP DNS校验处拒绝。未使用用户Key，未调用付费模型，也未修改系统DNS、代理、Codex或实际.env。真实Key模型列表成功仍需用户在原表单重试。
