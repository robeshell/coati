# 个人渠道迁移契约与实施顺序

状态：源码核对、账号归属/平台隔离及个人模型目录/调用链路已实现；Node 本人管理 API 已实现，Python 字段/路径兼容和控制台仍待完成；本人模型发现、手动检查、创建后探活和后台恢复探测已实现。此文不是完整交付声明。

## Python 事实依据

- `portal/backend/app/agent/api/my_channels.py`：本人渠道列表、供应商/协议目录、创建/编辑/删除、模型发现和检查；管理会话鉴权，菜单 `agent_my_channels` 及 add/edit/delete/test 按钮权限。
- `service/credential_service.py`：最多 5 条（包括停用渠道）；所有权由登录用户赋值；修改、删除、检查和复用已存凭证发现模型均先验证本人所有权，其他人的 ID 返回 404。删除必须停用且解除路由引用。创建后探活，探活失败不回滚已创建渠道。
- `model/__init__.py`：前缀去首尾空白，末尾 `/` 或 `-` 原样保留，否则追加 `/`。公开名称是前缀加实际模型；只有声明的模型才能反向剥离前缀；默认模型纳入声明列表。
- `service/gateway_service.py::resolve_routes`：优先匹配当前用户启用的个人渠道；匹配到个人候选后在个人池内选路。不能把个人凭证加入公共自动账号池。
- `_resolve_personal_routes`：冷却检查、优先级、带用户/模型范围的会话亲和、候选故障转移、凭证解密、公开/实际模型分离。没有可用个人渠道返回错误，不能悄悄改用平台渠道。
- 模型目录仅添加当前用户启用、供应商可用且协议适用的个人模型，并与平台目录去重；不能暴露其他用户的模型前缀。

以上 service/model 路径均相对于 `portal/backend/app/agent/`。供应商设置、代理、超时及自定义请求头仍需逐项核对，不得以简化 CRUD 视为完整迁移。

## Node 实施顺序

1. 先扩展账号 scope、owner 和 model_prefix 数据约束，现有账号默认平台范围；平台管理、候选路由、公开账号池、迁移预检、探活接口同步加范围约束。不能先开放写入口再补隔离。
2. 实现本人 CRUD 与兼容接口，限额检查在数据库事务内串行化，防止并发突破五条；请求体不能指定或修改 owner/scope。沿用现有加密、网络策略、CSRF 和权限组件。
3. 贯通个人模型目录和请求执行；密钥所属用户确定渠道所有权，原有模型授权与共享配额仍需检查。发送前再次检查所有权、启用、模型声明和冷却；本人池内处理亲和及故障转移，执行快照标识来源。
4. 补齐模型发现/探活、字段兼容及本人控制台，再做页面与真实 HTTP 模拟上游验收。
5. 纳入 Python 数据导入、凭证重加密、删除用户策略与升级/回滚演练。

## 必须证明的隔离与行为

- 两用户相同前缀/模型分别命中各自凭证；任意 ID 猜测不暴露对方配置或触发上游。
- 平台列表、路由绑定、自动池、预检和供应商汇总不把个人账号当平台账号。
- 并发创建上限、停用后发送前拒绝、删除引用检查、模型授权、预算预留/结算都有效。
- 三协议 JSON/SSE、公开模型回写、工具调用、缓存明细、取消及失败切换沿用完整执行链路。
- 使用隔离数据库和模拟上游；不以真实付费调用验证常规功能。

## 账号归属与平台隔离基础 — 2026-09-26

0028_gateway_personal_scope 为账号增加 scope、owner_user_id、model_prefix 和所有者索引/外键。数据库 CHECK 要求平台账号无所有者且无前缀；个人账号有有效所有者和非空前缀。现有账号迁移为 platform，不改变凭证或模型配置。

平台账号列表/更新/停用、迁移预检账号集合、路由列表中的账号详情、自动/显式候选、模型目录、探活候选/认领与请求发送前租约检查均排除个人账号。公共路由/显式路由仓储写入在事务内共享锁定目标账号并验证平台归属；平台保存方法不允许请求值修改归属。平台健康探活当前不会处理个人账号，后续本人探活需显式所有权参数和对应验证，不能移除隔离条件后复用。

此阶段没有开放个人渠道写入口，也没有把个人模型加入目录；后续必须完成上方全部实施步骤和隔离验证。

## 个人模型目录与调用链路 — 2026-09-26

模型目录按访问令牌 owner_id 增加本人启用渠道的公开名称，仍执行密钥模型授权。前缀规则沿用 Python：末尾 `/` 或 `-` 保留，否则补 `/`；默认模型与声明列表统一处理。执行优先匹配本人个人池，传给上游实际模型并回写公开名；个人池冷却时明确失败，不切入同名平台路由。冷却筛选使用数据库时钟。平台路径继续排除个人账号。

个人候选沿用受控传输、九组合桥接、模型授权、共享配额、租约、取消/结算生命周期；获取租约时重新检查归属、前缀、声明、启用和冷却状态。会话绑定仍按用户/公开模型/会话隔离，并在获取租约时核对当前绑定资格。优先级从高到低，故障转移仅在同一用户的匹配候选中进行。执行快照标识 route_kind=personal、route_id=null，不虚构平台路由 ID。健康回写携带发送时账号快照，检查 owner/scope、凭证、URL 和协议仍一致。平台后台探活暂不认领个人渠道。

26 项专项测试：18 个三协议 JSON/SSE 双轮工具调用组合（逐条校验公开/实际模型、实际认证头、缓存读取和用量结算、健康状态及租约清理）；3 种前缀形态；冷却不跨入平台池；模型授权/配额前置拒绝；租约时所有权与前缀再校验；两名真实用户的同名模型/同会话隔离；本人池内失败重试与后续会话绑定。全部使用隔离库和模拟上游。未据此宣称本人管理、个人探活、完整页面或真实供应商验收完成。

## 本人模型发现、检查与创建后探活 — 2026-09-26

新增 POST `/api/admin/gateway/my-channels/discover-models` 和 `/:id/check`，使用 gateway_my_channels_test 独立权限。保存凭证的发现仅限本人；不传新密钥时不能覆盖地址/协议。草稿发现必须提供新地址/密钥，即使带了新密钥也不能用别人的 credential_id。模型发现只返回建议列表，不更新声明模型或健康。仍使用受控网络传输、重定向限制、有限响应体和至多30秒期限。

手动检查复用数据库认领、失效时间、旧结果隔离和脱敏。认领带所有者条件；结果写入校验 scope/owner、密钥、URL、协议和观测时间。并发检查仅一个执行；删除会拒绝尚未结束的探测。Messages 列表不能证明对话健康，404/HTML/空结果保持未验证；失败不会延长冷却或增加硬惩罚。个人列表提供安全的探测时间、状态、延迟和脱敏错误，不暴露认领 token。

创建提交后进行一次检查；网络/上游/内部观察失败返回 health_probe，不把已保存渠道误报为创建失败。停用渠道沿用 Node 停用账号不探测的规则。平台后台任务仍只认领平台账号，个人定时恢复探测继续待补齐；旧版目录/字段/路径、代理/自定义头/超时和控制台也仍未完成。

## 个人渠道后台恢复探测 — 2026-09-26

恢复 worker 现在从平台/个人账号的共享候选队列选取最多五个账号，按最久未探测优先；每条候选携带数据库所有者信息。个人探测调用仍带所有者限定，归属改变后拒绝旧候选，不能降级成不带所有权的调用。普通平台查询/手动探测仍保持平台范围。后台沿用每分钟调度、十分钟静默期、数据库认领/超时/结果隔离，真实对话请求的更新不被更早的探测覆盖。

新增四项真实 PostgreSQL/本地模拟 HTTP 验证：两个服务实例竞争同一冷却个人账号仅发送一次并解除冷却；平台/个人共享五条批次上限，跳过停用和最近探测记录；Messages 列表保持未验证且静默期跨调用有效；归属变更后旧候选零上游调用。两服务实例在同一测试进程运行，不代表真实多进程崩溃/部署验收。此节完成此前记录的后台恢复待办；旧字段/路径/目录兼容及控制台继续待补齐。

## 账号自定义请求头与备注 — 2026-09-26

0030_gateway_account_headers 为平台及个人账号增加 extra_headers JSON 对象（旧账号默认空对象）与可空 note。原生管理接口支持保存、保留未传字段及显式清空，个人渠道响应只向本人返回配置。请求头支持对象或 JSON 对象字符串、空值清空、标量值归一化；最多20项，名称最多64字符，值最多512字符。禁止覆盖认证、Host、连接、长度、传输编码和 Cookie 头；非法名称、内部 CR/LF 拒绝。原生接口拒绝嵌套对象/数组作为头值；Python 旧接口的字段别名/宽松输入兼容仍需独立适配。

实际模型调用（九组合 JSON/SSE）、个人/平台检查和后台探测均使用账号请求头。只读发现默认使用保存配置，也可仅为本次发现覆盖或清空请求头，不改数据库。修改头配置后，旧探活或请求的健康观测不能回写新配置。上游错误与账本错误对请求头值脱敏，防止自定义头中携带的凭证进入错误诊断。

备注与请求头已迁移到原生管理和执行层；个人控制台、旧路径/字段/目录兼容、出站代理和账号级超时仍待补齐。

## 账号级超时接入（2026-09-26）

原生个人渠道现在保存 request_timeout_seconds（默认120秒，5–300秒整数），省略编辑保留原值。执行、保存账号模型发现、草稿发现、手动和后台检查均传递选定超时；配置变更阻止旧健康观察回写。传输采用等待响应头/响应体空闲超时，持续有数据的响应不因账号空闲期限结束。既有请求总期限180秒、连接10秒和发现30秒上限仍生效。个人页面与完整旧字段/路径兼容、代理尚未完成。

## 个人代理配置与执行（2026-09-26）

个人渠道支持proxy_url，完整值使用凭证保险库加密，列表只含proxy_hint/has_proxy。局部编辑省略保留，null或空值清除；创建探测、手动/后台探测及模型执行使用保存代理。模型发现可临时覆盖/清除代理但不修改记录，新草稿密钥不自动继承保存代理。删除/归属/凭证隔离继续沿用现有事务和权限限制。控制台和完整旧字段别名仍未交付。
