## 审查范围与发现

按请求链审阅登录/权限、网关授权与预留、上游发送、协议与工具转换、结算、旧数据导入、缓存接口和前端调用。这里记录的是本轮发现与验证，不是对所有供应商扩展或生产容量的保证。

| 问题 | 修复 |
|---|---|
| 管理台会话仅绑定用户名，同名重建可继承旧会话，改密不撤销旧会话 | 加密会话绑定用户 ID 与密码版本；登录重新核对身份；改密条件更新防止并发覆盖，只刷新当前会话；无效会话返回 401；重命名后刷新会话显示名，避免自删检查和审计使用旧用户名 |
| 服务端工具转换可能丢掉原始请求限制 | 转换前校验原始请求；状态型 Responses 进入既有拒绝链路；严格校验 max_uses，拒绝函数与服务端工具重名 |
| Responses 内嵌域名过滤没有应用到工具回退 | 读取 filters.allowed_domains，沿用工具域名验证 |
| 工具成功后的数据库结算错误被当成工具失败再次零结算 | 分离执行与结算；检查结算更新行数；结算失败携带请求 ID 并停止后续模型轮次；保留未结算记录供恢复处理 |
| HTTP 200 的上游错误包可能被记为成功 | 显式错误包按 upstream_error 处理，不回传空成功 |
| 旧缓存路径缺少旧客户端依赖的逐轮与汇总字段 | 对旧路径加返回适配；保留未知计数与历史原始字段；原生列表不加载完整结果 |
| 旧用量返回丢失父请求 ID | 从持久化上下文或工具原始用量恢复已记录的关联 |
| 大量 PAT 导入通过参数展开求最大 ID，有调用栈风险 | 改为线性归约；导入前校验模型数组、自定义头与个人账号归属，非法数据事务前拒绝 |

本轮没有增加数据库迁移，没有修改 Python 参考实现、真实账号密钥或机器配置。旧控制台 cookie 不满足新身份规则，需要重新登录；API 访问令牌不受 cookie 格式变化影响。

## 连续审计与页面收尾（2026-09-26）

继续审阅六组页面及对应服务，不把每次小修单独当作完成整个迁移。本次新发现并修复：

| 触发 | 修复与影响 |
|---|---|
| 快速切换缓存记录详情、关闭后旧请求才返回 | 详情请求使用代次，忽略过时结果；关闭/刷新失效旧请求，避免错误详情或重新弹出 |
| 缓存列表末页数据减少 | 回到最后有效页，不停在有总数却无记录的空页；轮数和输出上限必须整数 |
| 同一表单在按钮重新渲染前连续提交 | 共享表单同步提交锁，阻止重复创建或执行；成功/失败后释放 |
| 凭证列表刷新同时有旧请求在途 | 只应用最新列表响应，避免吊销/轮换后旧状态覆盖新状态；卸载时失效 |
| Chat/Responses使用内部Messages工具循环 | 请求账本记录真实入口协议，转换仍按内部协议执行；修正统计归属，不改变上游协议 |
| 第二轮模型发起抓取 | 工具子记录关联实际调用它的模型轮次；后续模型轮次仍关联根请求，保留完整树 |
| 旧通用账号页面探测按钮权限 | 使用test权限，与实际探测端点一致 |
