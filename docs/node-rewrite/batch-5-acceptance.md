## 修复与用户可见行为

- 会话标识按 Unicode 字符计数；超过64字符形成相同长度摘要。平台公开路由绑定命名空间包含路由、请求模型、实际模型；直接模型池使用 pool 命名空间。重新取路由时若映射已改变，不写入旧命名空间。数据库只存摘要，旧绑定自然过期，新请求建立新绑定。旧多候选路由架构的不同目标模型仍以首候选形成命名空间，账本S06保留差异。
- 未配置别名时，允许调用平台账号已声明的明确模型名；仍执行账号并发租约、模型授权、配额、健康筛选和亲和。已有公开/旧候选配置优先，停用配置不会被自动池绕过。`coati-auto`仍需显式自动路由，与Python要求一致。
- 接入 `AGENT_LLM_KEY/BASE/MODEL` 与 `AI_API_KEY/BASE/MODEL` 后备账号。三项齐备、模型匹配且无存储候选才使用；只在内存持有，不创建账号/绑定，执行快照标记environment、账号ID为空。个人池、停用公开路由及禁止回退绑定不会借此访问平台后备。
- 普通模型请求按Python字段集合的UTF8字节数/4预估输入。剩余额度不足以提供原输出预算时，在用户/令牌锁内缩减输出额度；真正发往上游的最大输出同步缩减。接入默认输出及最小completion空间环境配置，不覆盖已有令牌限额。
- Messages `thinking`不再一概拒绝；到Responses采用原Python的medium近似，到Chat沿用字段降级。工具`max_uses`支持0、大于8、整数字符串及非法值默认5，循环最多10轮，最后一轮移除服务端工具声明。
- 字段兼容策略默认`python`，跨协议沿用转换器对未识别字段的忽略/近似；请求头`x-coati-compatibility-policy: strict`启用显式不可转换字段检查。原生同协议继续透传。opaque签名、工具strict/并行控制、状态型Responses限制仍独立生效，不能将此选项理解为所有Python行为完全等价。
- 设备授权TTL、轮询间隔、确认路径与4-4用户码格式兼容旧配置；旧轮询接口返回Python格式的`error`说明及`error_code`机器码。Node新增的主动拒绝状态仍保留。
- 恢复探测支持旧间隔/批量/静默期配置（默认300秒/5个/600秒），独立worker仍需显式开启。Node开关优先于旧开关，不自动在API内启动探测。
- 真正的子进程在上游流中被SIGKILL后，过期请求与账号租约在同一事务清理；实际用量未知时不把预留量记作消费。实验人为推进数据库期限，不是等待完整TTL或生产容量测试。
- 个人用量近期请求改为浏览器本地时间，与请求日志一致；补齐令牌默认值及中断说明的英日翻译。
