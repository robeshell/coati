- Python 业务迁移已有实现与分层验收；原三协议、调度、授权、工具、额度契约是回归基线。
- 本地已拆分 `execution.ts`、`admin-service.ts`、`device-repository.ts`，并限制 HTTP 入口跨层访问。这是职责整理，不是运行时性能收益证据。
- 候选路由重新设计继续冻结，旧策略先以接口包装；不会借架构改造改掉配置。
- 新方案不自动改变模型能力目录语义、不引入响应缓存、不修改兼容默认值、不升级运行时主版本。
- 真实历史数据迁移和正式发布仍是交付事项，不能被本计划的性能测试代替。

## 3. 实施顺序与退出条件

### A. 基线与可观测性

处理 N12/N13，建立无付费的独立进程基准。首批内存采样与本地对账已执行，详细范围见 [内存基线报告](memory-baseline.md)。记录事件循环、CPU、RSS/Buffer、DB等待、分阶段延迟和业务对账。先修复旧benchmark账号声明；老脚本结果只保留历史诊断用途。

退出条件：基准能在固定环境复现；负载端/模拟上游不是瓶颈；能区分上游时间和网关开销；无凭证输出；退出清理自己创建的数据库/进程。只形成证据，不先许诺优化倍数。

回退：监测可关闭、采样可调，不影响授权或账本。

### B. Runtime、资源上限与连接复用

处理 N01/N02/N03/N04/N05/N07/N14。先集中资源所有权，再加上限和期限，最后复用代理池，避免先把池共享后仍沿用旧的destroy取消逻辑。

退出条件：既有协议/授权/用量回归通过；慢客户端与过载时内存受限、拒绝明确；取消不影响同池其他请求；凭证轮换、代理/TLS边界维持；退出能在宽限期内释放资源。与A阶段比较连接创建、CPU、尾延迟及池等待。

回退：保留旧transport工厂和默认行为切换，先在隔离环境验证；不得以回退开关绕过安全策略。

### C. 数据库热路径

处理 N06/N08/N11。以A/B的锁等待与查询计划确认优先点。配置缓存先行，额度投影和统计聚合分别迁移，禁止一次引入两套新计费权威。

退出条件：真实隔离DB迁移/回填演练；reserved、已结算、过期、跨日、并发多Key及历史导入对账一致；双写对照无漂移后才切换读路径。失败保持旧准入查询可用，绝不放宽硬额度。

回退：读模型可重建；停止相关写进程后切换到一致的旧读写版本。不能让未更新的旧实例继续写而漏计新投影。

### D. 协议适配演进

处理 N09，保留六个转换器作为对照基线，定义字段/事件/签名/原生扩展保真表。每次只迁一个方向或一类事件。

退出条件：同协议未知字段、六方向工具/推理/缓存/拒绝/截断/取消/结算证据不退化；差异明确；内存和CPU确有可解释收益或扩展性收益。若没有收益，不为统一形式强行替换稳定路径。

回退：按转换方向恢复旧实现，不改对外模型路由、不双发付费请求。

### E. 长任务与规模化统计

处理 N10/N15及N11中长期部分。复用PG认领worker；CPU池只在分析证明必要时加入。面向缓存验证/导出的异步任务新增创建、查询、取消、结果接口，不静默改变旧同步接口。

退出条件：任务状态/权限/租约/取消可恢复，API延迟不受重任务拖累；重复认领不被误当作供应商副作用幂等；结果保留和过期规则明确。

回退：暂停新任务准入、排空/标记在途任务后再切版本；不把数据库中旧任务丢弃。

### F. 收敛与交付

组合路径集中跑一次有限持续负载、两API故障恢复和账本对照。报告固定配置下的边界、失败模式及配置建议，不宣传所有供应商或生产容量。正式发布、真实历史迁移和上线切换仍走原交付验收。

## 2026-09-27：请求生命周期与节点保护

本批实现覆盖 API 的模型调用和外部搜索接口（含旧协议别名）。管理侧探测、缓存验证、导出及 worker 不计入这份准入预算。

- HTTP 在解析正文和鉴权前取得活动请求名额。默认每 API 进程 256 个；无等待队列，满载返回 503 / gateway_capacity / Retry-After: 1。原用户、Key、账号共享额度及 429 保持不变。
- 请求控制器关联客户端断开、总期限和节点排空；模型总期限使用现有 service timeout，外部搜索 70 秒。名额在响应结束且异步处理/流清理完成后归还，不能以 socket 关闭代替结算完成。
- 实例默认 64 MiB 字节预算，计入已收到的正文及当前待发送的编码流事件；输出按最多 64 KiB 分块拉取。正文超过预算在发送响应头前返回 503 / gateway_buffer_capacity；流已经开始后超预算会中断并取消上游，不伪造成功结束帧。
- 该预算不是 RSS 硬限制：解析后的 JS 对象、协议转换状态、非流式响应、Node/socket/TLS 缓冲不在该计数内，仍依靠现有单请求上限和活动请求上限。全链内存预算、池/连接总量仍待后续实现。
- 上游 idle 仅在等待下一次上游读取时计时，客户端暂停消费不再触发此计时；总期限仍持续。修复了流尚未消费即取消时生成器 finally 不执行导致预留未清理的路径。
- SIGTERM/SIGINT 或 app.close 先停止准入，/health 在排空期间返回 503；默认 10 秒宽限，到期取消活动请求，等待清理后关闭 transport 和自有 DB 池。取消后 HTTP 最多再等 1 秒断开未结束响应；数据库操作尚无统一硬期限，因此不能承诺任何 DB 故障下都准时退出。独立 liveness、worker/管理长任务排空未在本批完成。

配置：GATEWAY_MAX_ACTIVE_REQUESTS=256、GATEWAY_BUFFER_BUDGET_BYTES=67108864、GATEWAY_DRAIN_GRACE_MS=10000；已写入 .env.example 和 Compose，未修改用户现有环境文件。

源码：[runtime.ts](../../apps/api/src/modules/gateway/runtime.ts)、[request-lifecycle.ts](../../apps/api/src/modules/gateway/request-lifecycle.ts)、[runtime-http.ts](../../apps/api/src/modules/gateway/runtime-http.ts)、[execution.ts](../../apps/api/src/modules/gateway/execution.ts)。

验证：Node 22.19.0，本地模拟上游 + 隔离 PostgreSQL；最终 11 项网关定向检查、6 项 Runtime 检查通过，类型检查、受影响模块 ESLint、API 构建和网关静态门禁通过。覆盖准入/字节预算拒绝、断开后等待清理、未消费流取消、慢读与 idle/总期限区分、真实 HTTP 流排空及账本/账号租约释放，并复用授权、额度、SSE 定向回归。无真实供应商调用、容量压测或内存收益声明。
